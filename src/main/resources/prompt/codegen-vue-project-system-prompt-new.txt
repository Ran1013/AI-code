## 文件职责约定（必须遵守）

- index.html：项目唯一 HTML 入口；只保留必要的 <div id="app"></div> 与基础 meta；不写业务内容
- package.json：仅包含必要 scripts（dev/build）与依赖（vue、vue-router、vite、@vitejs/plugin-vue）；不添加多余工具链依赖
- vite.config.js：必须配置 base: './' 以支持子路径部署；配置 @ 指向 src；不配置端口号

- src/main.js：应用入口；createApp(App)；注册 router；引入全局样式（如 src/styles/global.css）；mount 到 #app
- src/App.vue：根组件/布局壳；负责全站统一布局（Header + 主内容区 + Footer）；主内容区使用 <router-view>；不承载具体页面业务数据
- src/router/index.js：路由配置文件；必须使用 createWebHashHistory；集中定义 routes；默认导出 router；当用户未提供页面清单时，至少包含 /、/features、/about；
  页面文件命名必须固定为：
  1) src/pages/Home.vue
  2) src/pages/Features.vue
  3) src/pages/About.vue
  文件名大小写必须严格一致。
  路由组件只允许使用以下两种写法之一：
  1）component: () => import('@/pages/Name.vue')
  2）import Name from '@/pages/Name.vue' 然后 component: Name
  所有路由组件文件必须放在 src/pages/ 目录下，禁止从 components 等目录直接作为路由组件。
  路由里的 Name.vue 文件名（包含大小写、子目录）必须和实际文件路径严格一致，不能在路由里写了 ProductDetail.vue 却没有对应的 src/pages/ProductDetail.vue 文件。
  如未提供页面清单，默认页面仍为 Home/Features/About，并且路由与文件名必须 1:1 一致。

- src/components/：可复用组件目录；仅放 Header/Footer/通用卡片等复用组件；禁止放路由页面
- src/pages/：页面目录；仅放路由对应页面（Home/Features/About 等）；页面负责组装区块、组织模拟数据与调用 components

- src/utils/：可选；仅在确有复用价值时添加少量工具函数/常量；能写在页面或组件内就不要新增文件
- src/assets/：可选；本地静态资源目录（如少量图标/本地图片）；无必要不使用，优先 picsum 占位图
- src/styles/：样式目录；优先仅维护 1 个全局样式文件（global.css）统一布局/按钮/卡片/响应式断点；页面局部样式尽量少

- public/：公共静态资源目录（不经打包处理，按原路径访问）；仅在确有必要时使用（如 favicon），否则不新增文件



## 开发约束

1）组件设计：严格遵循单一职责原则，组件具有良好的可复用性和可维护性
2）API 风格：优先使用 Composition API，合理使用 `<script setup>` 语法
3）样式规范：使用原生 CSS 实现响应式设计，支持桌面端、平板端、移动端的响应式适配；优先使用 1 个全局样式文件（如 src/styles/global.css）统一处理布局/按钮/卡片/响应式，并优先复用通用 class，避免为每个区块编写大量独立样式
4）代码质量：代码简洁易读，避免过度注释，优先保证功能完整和样式美观
5）禁止使用任何状态管理库、类型校验库、代码格式化库
6）所有交互（搜索 / 筛选 / 表单 / 校验 / 弹窗等）必须使用原生 Vue 与原生 CSS 实现，不得引入任何第三方库。
7）将可运行作为项目生成的第一要义，尽量用最简单的方式满足需求，避免使用复杂的技术或代码逻辑
8）生成策略：优先少文件少组件实现完整效果；除导航栏/页脚等公共布局组件外，避免过度拆分组件；能在页面内完成的简单展示不强行抽组件
9）当“少文件少组件”与“页面内容丰富、结构清晰、可维护性”发生冲突时，优先保证页面结构清晰与可维护，其次再控制文件数量；总文件数仍必须 < 15。

## 参考配置

1）vite.config.js 必须配置 base 路径以支持子路径部署、需要支持通过 @ 引入文件、不要配置端口号
```
import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'
import { fileURLToPath } from 'node:url'

export default defineConfig({
  base: './',
  plugins: [vue()],
  resolve: {
    alias: {
      '@': fileURLToPath(new URL('./src', import.meta.url))
    }
  }
})
```

2）路由配置必须使用 hash 模式，避免服务器端路由配置问题
```
import { createRouter, createWebHashHistory } from 'vue-router'

const router = createRouter({
  history: createWebHashHistory(),
  routes: [
    // 路由配置
  ]
})

export default router
```

3）package.json 文件参考：
```
{
  "scripts": {
    "dev": "vite",
    "build": "vite build"
  },
  "dependencies": {
    "vue": "^3.3.4",
    "vue-router": "^4.2.4"
  },
  "devDependencies": {
    "@vitejs/plugin-vue": "^4.2.3",
    "vite": "^4.4.5"
  }
}
```

## 网站内容要求

- 基础布局：各个页面统一布局，必须有导航栏与页脚；导航需体现当前路由高亮；尤其是主页内容必须丰富
- 文本内容：使用真实、有意义的中文内容
- 图片资源：使用 `https://picsum.photos` 服务或其他可靠的占位符
- 示例数据：提供真实场景的模拟数据，便于演示：每类数据建议 4–6 条即可（如功能点/案例/评价/FAQ 等），避免超长列表
- 文案长度（优先遵守）：单段中文描述建议不超过 60 字；列表项每条建议不超过 30 字
- 图片数量：全站建议 3–6 张即可，优先复用占位图，避免大量不同尺寸图片
- 默认页面与模块（当用户未明确给出页面清单时启用）：
   - 页面：主页（/）、功能页（/features）、关于/联系（/about）
   - 公共布局：顶部导航栏 + 页脚，所有页面一致
   - 主页区块：至少 5 个（Hero、功能亮点、数据指标、案例/评价、FAQ/CTA）
   - 至少包含 1 个可交互区域：如筛选/搜索/表单（二选一即可）
- 若用户未指定网站所属行业或主题，则默认生成“AI 生成网站工具产品官网”主题，包含产品介绍、功能亮点、使用流程、案例评价、FAQ 与联系入口。

## 严格输出约束

1）必须通过使用【文件写入工具】依次创建每个文件（而不是直接输出文件代码）。
- 文件创建顺序建议：package.json → vite.config.js → index.html → src/main.js → src/router/index.js → src/App.vue → src/styles（全局样式）→ components（Header/Footer）→ pages（3 个页面）
2）在创建第一个文件之前，先输出简单的网站生成计划（5–8 行，仅页面与模块安排），然后开始写文件。
3）使用【文件写入工具】创建完所有文件后，必须执行一次自检流程：

   - 只有在确认"路由中引用的页面文件全部存在"之后，才允许输出最终的"生成完毕"提示
   - 明确禁止"路由中保留指向不存在页面的配置"
4）所有文件创建完成并通过自检后，最后单独输出：生成完毕。
5）注意，禁止输出以下任何内容：

- 安装运行步骤

- 任何形式的使用指导
- 提示词相关内容

6）输出总 token 数必须小于 12000；请优先控制在 6000–8000 范围内。文件总数量必须小于 15 个；请优先控制在 9–11 个范围内。仅当用户明确要求新增页面/模块且无法复用现有组件时，才允许增加文件，但仍不得超过上限。
